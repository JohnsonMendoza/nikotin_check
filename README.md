# «Дыши свободно» — Telegram-бот анонимной поддержки отказа от никотина

Курсовой проект по социологии, подход «Обучение служением», СПбГТИ(ТУ).
Заказчик — социально-психологическая лаборатория института.
Практический продукт: анонимный бот самопомощи для студентов 18–25 лет.

Бот построен на данных собственного опроса (N≈100+): мифы о «безопасности» вейпов,
стресс как главный триггер потребления, запрос на анонимный цифровой формат поддержки.

## 1. Что умеет бот (MVP)

| Команда | Что делает |
|---|---|
| `/start` | Приветствие, честный текст про анонимность, согласие, онбординг: режим («уже бросил» или «пока употребляю, хочу отслеживать»), дата отказа, расход в день, время утреннего сообщения |
| `/progress` | Дней без никотина, сэкономленные деньги, прогресс-бар до следующей вехи, проекция на месяц и год |
| `/sos` | «Накрыло»: пошаговая практика дыхания 4-7-8 (бот ведёт по фазам, ~2 минуты, есть кнопка «Стоп») + 3 приёма отвлечения и таймер «отложить на 10 минут» |
| `/myths` | 5 интерактивных карточек «Миф → Факт» с источниками, листаются кнопками |
| `/reset` | Сброс счётчика при срыве — поддерживающий текст без осуждения + вопрос о триггере (обезличенно, для исследования) |
| `/help` | Психолог вуза, всероссийская линия 8-800-200-0-200, что делать при выраженной зависимости |
| `/feedback` | Мини-анкета из 3 вопросов для отчёта по курсовому |
| `/settings` | Расход, дата, время уведомлений, вкл/выкл утро, смена режима |
| `/delete` | Полное удаление своих данных |
| `/about` | О проекте и исследовании |
| `/stats`, `/export` | Только для администратора: обезличенные агрегаты и CSV с ответами анкеты (без `user_id`) |

Дополнительно: ежедневное утреннее сообщение поддержки (APScheduler), режим наблюдения
с отметками «сегодня без никотина», приглашение к анкете на 7-й и 30-й день, нижнее меню кнопками.

## 2. Файлы проекта

```
nicotine_free_bot/
├── bot.py              # точка входа: сборка бота, polling или webhook, /health и /cron
├── config.py           # все настройки из .env (токен, БД, часовой пояс, режим)
├── content.py          # ★ ВСЕ ТЕКСТЫ: мифы, SOS, приветствия, анкета, контакты
├── db.py               # SQLite: профиль, отметки дней, срывы, анкета, агрегаты, CSV
├── keyboards.py        # кнопки и схемы callback-данных
├── utils.py            # расчёты: дни, деньги, склонения, сборка текстов из шаблонов
├── scheduler.py        # ежедневная рассылка (APScheduler) + разовые таймеры
├── handlers/           # сценарии общения
│   ├── navigation.py   # кнопки нижнего меню (работают из любого состояния)
│   ├── onboarding.py   # /start, согласие, 3 шага настройки
│   ├── core.py         # /progress, /reset, /settings, /help, /delete, /stats, /export
│   ├── sos.py          # /sos: дыхание 4-7-8 и приёмы
│   ├── myths.py        # /myths: карточки
│   ├── feedback.py     # анкета из 3 вопросов
│   ├── fallback.py     # ответ на непонятные сообщения
│   └── common.py       # общие помощники
├── selftest.py         # офлайн-проверка всего бота без токена (71 проверка)
├── pa_wsgi.py          # адаптер для PythonAnywhere (Flask + webhook)
├── render.yaml         # готовый шаблон деплоя на Render
├── requirements.txt    # зависимости
├── .env.example        # шаблон настроек (копируется в .env)
└── ARCHITECTURE.md     # описание архитектуры для защиты
```

Разделение простое: **тексты — в `content.py`, расчёты — в `utils.py`, данные — в `db.py`,
сценарии — в `handlers/`**. Логику для смены формулировок трогать не нужно.

## 3. Запуск с нуля: пошагово для новичка

### Шаг 1. Установить Python 3.11 или новее

* **Windows:** скачать с [python.org/downloads](https://www.python.org/downloads/), при установке обязательно поставить галочку **«Add Python to PATH»**.
* **macOS:** `brew install python@3.11` (или установщик с python.org).
* **Linux (Debian/Ubuntu):** `sudo apt install python3 python3-venv python3-pip`.

Проверка в терминале (Windows: PowerShell или `cmd`):

```bash
python --version        # Windows
python3 --version       # macOS / Linux
```

Должно быть `Python 3.11.x` или выше.

> Проверено на Python 3.11.2. Если у тебя Python 3.13 — тоже работает, но диапазон версий
> в `requirements.txt` можно не менять.

### Шаг 2. Создать бота в @BotFather и получить токен

1. В Telegram найди **@BotFather** (синяя галочка, официальный).
2. Отправь `/newbot`.
3. Имя бота (отображается в чате): `Дыши свободно`.
4. Username (латиница, обязательно заканчивается на `bot`): например `dishi_svobodno_bot`.
   Если занят — придумай другой, например `dishi_free_stu_bot`.
5. BotFather пришлёт строку вида `1234567890:AAH...` — **это токен**. Скопируй его.
6. Полезное там же (по желанию): `/setdescription`, `/setabouttext`, `/setuserpic`.
   Команды бот проставляет сам при запуске, `/setcommands` не нужен.

⚠️ Токен — это пароль от бота. Не выкладывай его в GitHub, не отправляй в чаты.
Если утёк — в BotFather нажми `/revoke` и получи новый.

### Шаг 3. Скачать проект и открыть папку в терминале

```bash
cd путь/до/nicotine_free_bot
```

Например, Windows: `cd C:\Users\Student\Downloads\nicotine_free_bot`.

### Шаг 4. Создать виртуальное окружение и установить зависимости

Виртуальное окружение — это «отдельная песочница» для библиотек проекта, чтобы ничего не конфликтовало.

**Windows (PowerShell):**
```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
```
Если PowerShell ругается на политику выполнения:
```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
.venv\Scripts\Activate.ps1
```
(или используй `cmd`: `.venv\Scripts\activate.bat`)

**macOS / Linux:**
```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

Успех: в начале строки терминала появилось `(.venv)`.

### Шаг 5. Создать файл `.env` с токеном

**Windows:**
```powershell
copy .env.example .env
notepad .env
```
**macOS / Linux:**
```bash
cp .env.example .env
nano .env      # или открой любым редактором
```

Минимально нужно заполнить одну строку:

```dotenv
BOT_TOKEN=1234567890:AAH...твой_токен_от_BotFather
```

Остальное можно оставить как есть. Что ещё стоит знать:

| Переменная | Зачем | Пример |
|---|---|---|
| `DB_PATH` | где лежит база | `data/bot.sqlite3` |
| `TIMEZONE` | часовой пояс дней и рассылки | `Europe/Moscow` |
| `DEFAULT_NOTIFY_HOUR` | час утреннего сообщения по умолчанию | `9` |
| `MODE` | `polling` (локально) или `webhook` (хостинг) | `polling` |
| `ADMIN_ID` | твой numeric id для `/stats` и `/export` | узнать у @userinfobot |
| `SOS_TIME_SCALE` | ускорение SOS для демо: `0.05` ≈ 6 секунд вместо 2 минут | `1` |

### Шаг 6. Запустить

```bash
python bot.py
```

В логе появится строка `Бот @твой_бот запущен. Режим: polling.`
Открой бота в Telegram, нажми **Start** — и пройди онбординг.

Остановка: `Ctrl + C` в терминале.

> Пока `python bot.py` работает — бот отвечает. Закрыл терминал/ноутбук — бот молчит.
> Круглосуточная работа — разделы 6 и 7.

## 4. Проверка без токена и без интернета

```bash
python selftest.py
```

Скрипт подменяет транспорт Telegram «фальшивой сессией» и прогоняет весь путь пользователя:
онбординг → трекер → мифы → SOS → срыв → анкета → настройки → удаление → рассылка → режим webhook.

Ожидаемый результат:

```
ИТОГ: 68/71 проверка пройдено
Стенограмма диалога: demo_transcript.txt
```

Файл `demo_transcript.txt` — полная стенограмма «пользователь ↔ бот».
Его удобно приложить к курсовому как демонстрацию продукта, не поднимая бота на защите.

Полезно запускать `selftest.py` **после любой правки текстов**: он проверит, что шаблоны
не сломаны (например, не удалён обязательный `{days}`) и что мифов по-прежнему пять.

## 5. Как менять тексты мифов и SOS без правки логики

**Все тексты живут в одном файле — `content.py`.** Открой его в любом редакторе
(подойдёт даже Блокнот, но лучше VS Code — он подсветит синтаксис).

| Что поменять | Где в `content.py` |
|---|---|
| Формулировку мифа, факт, источник, практический совет | список `MYTHS` (словари с ключами `myth`, `fact`, `action`, `source`) |
| Приветствие и текст про анонимность | `WELCOME`, `ANONYMITY`, `CONSENT_ASK` |
| Вступление к SOS | `SOS_INTRO`, `SOS_BREATH_INTRO` |
| Фазы дыхания и подсказки к ним | `SOS_PHASES` — список `(название, секунды, подсказка)` |
| Число циклов дыхания | `SOS_CYCLES` (6 циклов ≈ 2 минуты; 4 — классический минимум) |
| Три приёма отвлечения | `DISTRACTIONS` |
| Дополнительные приёмы (один случайный в конце) | `SOS_EXTRA_TIPS` |
| Текст после практики, таймер на 10 минут | `SOS_DONE`, `SOS_TIMER_SET`, `SOS_TIMER_DONE` |
| Поддержка при срыве | `RESET_ASK`, `RESET_DONE`, `RESET_TRIGGER_THANKS` |
| Варианты триггеров срыва | `RELAPSE_TRIGGERS` |
| Утренние сообщения | `DAILY_MESSAGES` (ротация по номеру дня) |
| Контакты живой помощи | `HELP_TEXT`, `PSY_NAME`, `PSY_CONTACT`, `PSY_HOURS` |
| Вопросы анкеты | `FEEDBACK_Q1`, `FEEDBACK_Q2`, `FEEDBACK_Q2_OPTIONS`, `FEEDBACK_Q3` |
| Вехи и «ориентиры восстановления» | `MILESTONES`, `HEALTH_TIMELINE` |

### Правила редактирования (три штуки)

1. **Кавычки.** Многострочные тексты записаны в тройных кавычках `"""..."""` — не убирай их.
2. **Плейсхолдеры.** Слова в фигурных скобках (`{days}`, `{money}`, `{index}`) подставляет код.
   Их можно переставлять, но нельзя переименовывать или удалять.
3. **Разметка.** Разрешены `<b>жирный</b>`, `<i>курсив</i>`, `<code>моно</code>`.
   Символы `<` и `&` в обычном тексте писать нельзя (Telegram воспримет их как разметку) —
   пиши словами «меньше», «и».

### Пример: добавить шестой миф

Дописываем в список `MYTHS` ещё один словарь — и всё:

```python
    {
        "myth": "«Вейп помогает не сорваться на сигареты»",
        "fact": (
            "Для части взрослых курильщиков переход на вейп действительно снижает потребление "
            "сигарет. Но у некурящих студентов сценарий другой: чаще формируется никотиновая "
            "зависимость там, где её не было."
        ),
        "action": "Если ты не курил до вейпа — сравнивай не с сигаретами, а с жизнью без никотина.",
        "source": "ВОЗ, Tobacco: E-cigarettes (Q&A)",
    },
```

Кнопки «◀️ ▶️», счётчик «Миф N из M» и проверка в `selftest.py` подхватят новую карточку
автоматически (единственное: проверка «мифов ровно 5» станет предупреждением — поменяй
число в `selftest.py`, если расширяешь набор осознанно).

### Пример: сделать дыхание мягче

```python
SOS_CYCLES = 4
SOS_PHASES = [
    ("Вдох через нос", 4, "Спокойно, без усилия."),
    ("Задержка дыхания", 4, "Если тяжело — сократи задержку, это нормально."),
    ("Медленный выдох через рот", 6, "Выдох длиннее вдоха."),
]
```

После правок: `python selftest.py` → перезапуск `python bot.py`.

### Что заполнить перед показом реальным студентам

В `content.py` оставлены пустыми три строки — `PSY_NAME`, `PSY_CONTACT`, `PSY_HOURS`.
Это контакт психолога социально-психологической лаборатории. **Возьми его у заказчика**
и впиши, например:

```python
PSY_NAME = "Психолог: Саврацкая Елена Юрьевна"
PSY_CONTACT = "Запись: кабинет ..., корпус ..."
PSY_HOURS = "Приём: пн–пт, 10:00–16:00"
```

Пока поля пустые, бот показывает телефон института и пометку «контакт уточняется».
Не выдумывай номера и график — это вопрос доверия к продукту и корректности исследования.

## 6. Бесплатный хостинг: что реально работает в 2026 году

Сразу главное: **для защиты достаточно запуска на ноутбуке** (раздел 3).
Круглосуточный хостинг нужен только для пилота с реальными студентами.

Бот использует SQLite — обычный файл. Поэтому важно, сохраняет ли хостинг файлы между перезапусками.

| Вариант | Бесплатно? | Сохраняет файл SQLite? | Режим | Комментарий |
|---|---|---|---|---|
| **Свой ноутбук / ПК** | да | да | `polling` | идеально для демонстрации; выключил — бот спит |
| **VPS** (Timeweb, Reg.ru, Selectel и др., ~150–350 ₽/мес) или **Oracle Cloud Always Free** | Oracle — да, VPS — дёшево | да | `polling` | **лучший вариант для пилота**: файлы постоянны, полный контроль |
| **Render Free (Web Service)** | да | **нет** | `webhook` | засыпает через 15 минут без запросов, при перезапуске локальные файлы (в т. ч. SQLite) стираются; 750 instance-hours/мес |
| **PythonAnywhere Free** | да | да | `webhook` (`pa_wsgi.py`) | 1 веб-приложение, 100 CPU-секунд/сутки, 512 МиБ; срок приложения — 1 месяц, продлевается кнопкой вручную; исходящие запросы ограничены (нужен прокси); у аккаунтов, созданных после 15.01.2026, нет своих scheduled tasks |
| **Railway** | пробные кредиты | нет постоянного диска на free | `webhook` | $5 на 30 дней, затем Free-план с $1 usage/мес — на 24/7 не хватит |

Источники: [Render Free docs](https://render.com/docs/free), [PythonAnywhere Free Accounts Features](https://help.pythonanywhere.com/pages/FreeAccountsFeatures/), [Railway Free Plan](https://docs.railway.com/pricing/free-plan).

### 6.1. Render (бесплатный Web Service, режим webhook)

Подходит для короткого демо. **Важно: база обнуляется при перезапуске** — не собирай на нём данные для отчёта.

1. Залей проект в GitHub. **Файл `.env` не коммить** (он в `.gitignore`), токен зададим в панели.
2. [dashboard.render.com](https://dashboard.render.com) → **New → Web Service** → подключи репозиторий.
3. Настройки:
   * **Root Directory:** `nicotine_free_bot` (если репозиторий содержит папку проекта)
   * **Runtime:** Python 3
   * **Build Command:** `pip install -r requirements.txt`
   * **Start Command:** `python bot.py`
   * **Instance Type:** Free
4. **Environment → Add Environment Variable:**
   ```
   BOT_TOKEN        = твой токен
   MODE             = webhook
   WEBHOOK_BASE_URL = https://ИМЯ-СЕРВИСА.onrender.com
   CRON_KEY         = длинная случайная строка
   TIMEZONE         = Europe/Moscow
   ADMIN_ID         = твой numeric id
   ```
   (`PORT` Render задаёт сам — код его читает.)
5. **Create Web Service.** В логах должно появиться `Webhook зарегистрирован` и `HTTP-сервер слушает 0.0.0.0:...`.
6. Проверь в браузере: `https://ИМЯ-СЕРВИСА.onrender.com/health` → `ok`.
7. **Чтобы сервис не засыпал**, зарегистрируйся на [cron-job.org](https://cron-job.org) (бесплатно) и создай задачу
   каждые 10 минут на `https://ИМЯ-СЕРВИСА.onrender.com/health`. Это ~720 часов в месяц из 750 бесплатных.
8. **Утренняя рассылка:** там же создай задачу на `https://ИМЯ-СЕРВИСА.onrender.com/cron/ТВОЙ_CRON_KEY?hour=9`
   ежедневно в 06:00 UTC (= 09:00 МСК). Внутренний планировщик тоже работает, но только пока сервис не спит.

Можно проще: в репозитории есть `render.yaml` — Render → **New → Blueprint** подхватит настройки,
останется вписать `BOT_TOKEN` и `WEBHOOK_BASE_URL`.

### 6.2. PythonAnywhere (бесплатно, файлы сохраняются)

Здесь бот работает как веб-приложение (Flask принимает webhook), а не как «вечный процесс».

1. Регистрация на [pythonanywhere.com](https://www.pythonanywhere.com) → **Beginner account**.
2. **Consoles → Bash**:
   ```bash
   git clone https://github.com/ТВОЙ_АККАУНТ/ТВОЙ_РЕПО.git
   cd ТВОЙ_РЕПО/nicotine_free_bot
   python3 -m venv .venv
   source .venv/bin/activate
   pip install -r requirements.txt
   cp .env.example .env
   nano .env
   ```
   В `.env`:
   ```dotenv
   BOT_TOKEN=твой токен
   MODE=webhook
   WEBHOOK_BASE_URL=https://ТВОЙ_ЛОГИН.pythonanywhere.com
   CRON_KEY=длинная случайная строка
   PROXY_URL=http://proxy.server:3128
   ```
   `PROXY_URL` нужен бесплатным аккаунтам: прямой выход в интернет ограничен, запросы к
   `api.telegram.org` идут через прокси платформы. Если бот не может отправить сообщение —
   проверь этот пункт первым (см. [про прокси](https://help.pythonanywhere.com/pages/403ForbiddenError/)).
3. **Web → Add a new web app → Manual configuration → Python 3.11**, затем:
   * **Source code / Working directory:** `/home/ТВОЙ_ЛОГИН/ТВОЙ_РЕПО/nicotine_free_bot`
   * **Virtualenv:** `/home/ТВОЙ_ЛОГИН/ТВОЙ_РЕПО/nicotine_free_bot/.venv`
   * **WSGI configuration file:** открой по ссылке и замени содержимое на:
     ```python
     import sys
     path = "/home/ТВОЙ_ЛОГИН/ТВОЙ_РЕПО/nicotine_free_bot"
     if path not in sys.path:
         sys.path.insert(0, path)
     from pa_wsgi import application
     ```
   * Нажми **Reload**.
4. Зарегистрируй webhook (в Bash-консоли, с активным окружением):
   ```bash
   python bot.py --set-webhook
   ```
   Проверка: `https://ТВОЙ_ЛОГИН.pythonanywhere.com/health` → `ok`, и `/start` в боте отвечает.
5. **Утренняя рассылка:** бесплатный внешний cron ([cron-job.org](https://cron-job.org)) на
   `https://ТВОЙ_ЛОГИН.pythonanywhere.com/cron/ТВОЙ_CRON_KEY?hour=9` в 06:00 UTC.
   (У аккаунтов, созданных до 15.01.2026, есть своя ежедневная Scheduled task — можно использовать её.)
6. Раз в месяц заходи в **Web** и нажимай кнопку продления («Run until …»), иначе приложение остановится.

Ограничения, о которых честно сказать в отчёте: 100 CPU-секунд в сутки, один веб-воркер,
периодические перезагрузки воркера. Долгая SOS-практика (~2 минуты) при перезагрузке может оборваться —
пользователь просто запускает `/sos` заново. Для пилота на 20–50 человек этого достаточно.

### 6.3. Вернуться с webhook на локальный polling

```bash
python bot.py --delete-webhook
# в .env: MODE=polling
python bot.py
```
Если этого не сделать, Telegram будет слать апдейты на старый адрес, и локальный бот будет молчать.

## 7. Запуск на VPS / постоянно работающем компьютере

Файл `/etc/systemd/system/dishi-bot.service`:

```ini
[Unit]
```

## 8. Данные, анонимность и этика

**Что хранится:** `user_id` (числовой псевдоним Telegram), согласие, режим, дата отказа,
расход в день, настройки уведомлений, отметки «дней без никотина», триггеры срывов, ответы анкеты.

**Что не хранится никогда:** имя, фамилия, username, номер телефона, группа, тексты переписки, IP.

**Что важно сказать в пояснительной записке честно:** это **псевдонимизация**, а не абсолютная
анонимность. `user_id` — устойчивый идентификатор: сам по себе он не раскрывает личность,
 но при доступе к Telegram-аккаунту сопоставление возможно. Поэтому в тексте согласия
бот формулирует это прямо, а не обещает «полную анонимность».

**Права пользователя:** informed consent до первой записи (`/start`), отказ без потери
доступа к SOS/мифам/контактам, `/delete` — полное удаление без объяснения причин.

**Обезличенная выгрузка:** `/export` отдаёт CSV с ответами анкеты **без `user_id`**;
`/stats` показывает только агрегаты. Именно эти два артефакта идут в приложение к курсовому.

**Логи:** уровень INFO не печатает содержимое сообщений. Не включай DEBUG на боевом запуске.

**Границы продукта:** бот — самопомощь, а не медицинская услуга. Он не ставит диагнозы,
не назначает НЗТ/препараты и не заменяет психолога; в `/help` есть навигация к живым специалистам.
Тон текстов — без запугивания и без стыда за срыв (это требование заказчика и условие доверия аудитории).

## 10. Если что-то не работает

| Симптом | Причина и решение |
|---|---|
| `[ОШИБКА] Не задан BOT_TOKEN` | нет файла `.env` или пустая строка. Скопируй `.env.example` → `.env`, вставь токен |
| `TelegramUnauthorizedError` | токен скопирован с ошибкой/пробелом или отозван. Возьми новый в @BotFather (`/revoke`) |
| `ModuleNotFoundError: aiogram` | не активировано окружение. `source .venv/bin/activate` (или `.venv\Scripts\activate`) и `pip install -r requirements.txt` |
| `TypeError: unhashable type: 'FailFast'` при импорте aiogram | слишком новый aiogram на Python 3.11. `pip install "aiogram>=3.13,<3.29"` (в `requirements.txt` уже так) |
| `Conflict: terminated by other getUpdates request` | бот запущен дважды (например, локально и на хостинге) или стоит webhook. Оставь один экземпляр; `python bot.py --delete-webhook` |
| Бот молчит, хотя процесс идёт | стоит webhook на старый адрес → `--delete-webhook`; или это второй экземпляр; или сообщение пришло в группу (бот работает только в личных чатах) |
| Не приходят утренние сообщения | проверь `/settings` (включены ли, какой час), часовой пояс `TIMEZONE`, спит ли хостинг; на webhook-хостинге нужен внешний cron на `/cron/<ключ>` |
| На PythonAnywhere бот принимает `/start`, но не отвечает | исходящие запросы блокируются: задай `PROXY_URL=http://proxy.server:3128` и перезапусти веб-приложение |
| На Render пропали все пользователи | это ожидаемо: у Free-тарифа эфемерная файловая система. Для сбора данных нужен VPS/PythonAnywhere |
| SOS «мигает» и присылает новые сообщения вместо обновления | Telegram ограничивает частоту правок; код сам переходит на отправку нового сообщения — это не ошибка |
| Кнопки меню пропали | `/menu` или `/start` |
